# Agent tables — contract for the four Glean agents

Status: v1, 2026-11-18. Schema from migration `0019_agent_tables`.

Each Glean agent owns one flat table. The app keeps its old table names as views on these tables,
same columns, so app code is unchanged. Agents read and write the tables below, never the views.

| # | Agent | Writes | Reads | Old name (now a view) |
|---|---|---|---|---|
| 1 | Web intelligence | `web_snapshot` | `agent_catalog` | `snapshot` |
| 2 | Extraction | `page_extraction` | `web_snapshot` | `extraction` |
| 3 | Drift score | `drift_score`, and status columns of `conflict` | `page_extraction`, `agent_catalog`, `conflict`, `drift_score` | `score_snapshot` |
| 4 | AEO / GEO | `aeo_response` (+ one `ai_run` row per batch, optional) | `agent_catalog`, `ai_prompt`, `prompt_variant`, `persona`, `run_config`, `competitor`, `conflict`, `drift_score.truth` | `ai_answer`, `answer_mention`, `answer_claim`, `answer_citation` |

## Rules for every agent table

- `id` is `GENERATED BY DEFAULT AS IDENTITY`. Agents may leave it out; the database assigns it.
- Load = `INSERT ... ON CONFLICT (<natural key>) DO UPDATE`, so loading the same file twice changes nothing.
- `agent_run_id` = the Glean run id. Null on rows the app writes itself.
- Copied columns (url, retailer, names, weight) are a snapshot taken at write time. The app never
  reads them. For the current page weight read `agent_catalog`.
- Generated columns (`page_extraction.*_value`, `drift_score.drift`) are computed by Postgres: leave
  them out of the CSV / insert.
- FKs are real: `sku_id`, `page_id`, `prompt_id` must exist (take them from `agent_catalog` / `ai_prompt`).

## web_snapshot (agent 1)

One fetch of one URL. Natural key `(page_id, content_hash)`: the same HTML again is not a new row.
The migration adds this unique key only when existing data has no repeats (the current local data
has some), so until it exists, check for the pair before inserting.

`id, organisation_id, page_id, fetched_at, content_hash, html, url, final_url, http_status,
fetch_status (ok|blocked|error), error, retailer, source_type, country, page_weight, sku_id, brand_id,
sku_name, brand_name, gtin, agent_run_id`

`content_hash` = sha256 of `html`. URLs to fetch: `SELECT page_id, url, sku_id FROM agent_catalog`.

## page_extraction (agent 2)

One snapshot x one SKU. Natural key `(snapshot_id, sku_id)`.

`id, organisation_id, snapshot_id, sku_id, fields, created_at, page_id, fetched_at, url, retailer,
page_weight, brand_id, status, method, rules_version, warnings, agent_run_id`
plus generated `name_value, ingredients_value, free_from_value, claims_value, seals_value`.

`fields` = `{field: {"value": ..., "quote": "..."}}` (extraction-agent.md §3). `sku_id` comes from
`web_snapshot.sku_id`, so no `page.csv` / `page_sku.csv` is needed. Only readable product pages get
a row (extraction-agent.md §6).

## drift_score (agent 3)

One SKU at one run: one row per SKU per `run_at` (`taken_at`).

`id, organisation_id, brand_id, sku_id, taken_at, score, weighted_severity, page_weight, unresolved,
by_verdict, by_status, mean_days_to_fix, is_demo, sku_name, brand_name, truth_source, truth, findings,
new_count, reopened_count, resolved_count, agent_run_id` plus generated `drift` (= 100 - score).

The first 13 columns are the old `score_snapshot` columns, same formulas (conflict-score-agent.md §7).
`truth` = the 5-field truth used. `findings` = `[{page_id, field, verdict, severity, page_value, truth_value}]`.
`conflict` is reconciled and loaded as before (conflict-score-agent.md §6 and §9).

## aeo_response (agent 4)

One LLM call. Natural key `call_key` (agent-made hash of prompt, variant, persona, engine, model,
region, language, search, sample, asked_at).

All 30 old `ai_answer` columns, then `mentions, claims, citations` (JSON arrays), `brand_name,
sku_name, prompt_intent, funnel_stage, persona_name, own_mentioned, own_recommended, call_key, agent_run_id`.

- `mentions`: `[{name, brand_id, competitor_id, is_own, position, recommended, sentiment, quote}]`
- `claims`: `[{sku_id, field, value, quote, verdict, severity, echo_conflict_ids}]` (verdict null = matches truth)
- `citations`: `[{url, domain, title, page_type}]`

Arrays are append-only. Never reorder or remove elements: the app's child views number them by
position (`id = answer_id * 1000 + position`).

## agent_catalog (view, read only)

One row per page: `page_id, organisation_id, organisation_name, url, source_type, retailer, country,
page_weight, sku_id, sku_name, gtin, line, sku_aliases, brand_id, brand_name, brand_aliases,
truth_sheet (latest approved value per field), has_truth_sheet, evidence_url`.

The page -> SKU link is the new `page.sku_id` column (filled from existing extractions by the migration).

## After each load (follow-up step)

A load fills the agent tables and `conflict`. The app's own check run also writes history, alerts,
the inferred truth and the "last checked" date; run the follow-up so agent runs do the same
(`backend/app/agent_sync.py`, reuses the app's functions, safe to run twice):

```bash
uv run python -m app.agent_sync drift --run <agent_run_id>   # after a drift_score + conflict load
uv run python -m app.agent_sync aeo                           # after an aeo_response load
```

`drift` relies on the drift agent stamping `conflict.detected_at` / `status_changed_at` and
`drift_score.taken_at` with the same `run_at` (conflict-score-agent.md §2 and §6).

Once the drift agent is the source of truth, set `DRIFT_SOURCE=agent` for the worker
(`app.worker`), so its scheduled product checks stop writing `conflict` and `score_snapshot` too.
The manual Run check button and truth-sheet save still run the app's own check.
